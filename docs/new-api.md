# API страницы carV2

Проверено 21 октября 2026 года по загруженному коду официального сайта
`https://app.evassist.ru/assets/index-YkNVXOWl.js` и ответам API аккаунта.
Токены и персональные данные в репозиторий не включены.

## Команды и подтверждения

Сайт отправляет команду через `POST /client-bff-service/telemetry-commands`:

```json
{"commandName": "centralLockingOn", "imei": "<IMEI тбокса>"}
```

Ответ 201 содержит `commandId` (UUID). Статус читается через
`GET /client-bff-service/telemetry-commands/{imei}`. Это **последняя команда
устройства**, а не поиск по UUID. Ответ может быть пустым. Поля ответа:
`commandId`, `commandName`, `status`, `createdAt` и служебные идентификаторы.

| Статус | Подпись сайта |
|--------|---------------|
| `pending` | Отправлена |
| `delivered` | Доставлена |
| `success` | Выполнена |
| `error` | Не выполнена |

Сайт опрашивает статус каждые 1,5 секунды и принимает его только при совпадении
`commandId`. В коде сайта указан срок подтверждения машиной 45 секунд.
Интеграция ждёт до 50 секунд. HTTP-ответ об отправке не означает исполнения.
При таймауте POST, потере статуса или смене UUID интеграция не повторяет команду
и не переключается на старую команду-переключатель.

Разрешённый живой тест: один POST `centralLockingOn`, затем один POST
`centralLockingOff`. Перед тестом свежая телеметрия показывала закрытый замок,
онлайн и паркинг. Закрытие прошло через `delivered` и `success`; открытие к первому
опросу уже имело `success`. После открытия свежая телеметрия подтвердила
`isCentralLockingOn: false`. Остальные команды не отправлялись.

## Возможности машины

`GET /client-bff-service/telemetry/{imei}` уже был основным источником данных
интеграции. Его `buttons` описывает доступные команды и их состояния:

| Назначение | Включить / открыть | Выключить / закрыть |
|------------|---------------------|--------------------|
| Центральный замок | `centralLockingOff` | `centralLockingOn` |
| Прогрев | `heatingOn` | `heatingOff` |
| Охлаждение | `coolingOn` | `coolingOff` |
| Багажник | `trunkOpen` | `trunkClose` |
| Поиск | `search` | `search` |
| Подготовка к поездке | `tripPreparationOn` | `tripPreparationOff` |

Названия взяты из ответа проверенной машины; доступность зависит от её профиля.
Интеграция учитывает `enabled` и перечень кнопок, не отправляет команды при
полученном состоянии «оффлайн» или «не в паркинге», проверяет требования закрытия
багажника и замка, как сайт. Во время выполнения одной команды вторая отклоняется,
а не откладывается в очередь.

Подготовка к поездке по профилю сайта отправляется без параметров. Для неё добавлены
отдельные кнопки и индикатор в HA. Старый `PREPARE` с температурой, временем,
подогревом сидений и руля сохранён отдельно: эти параметры не подменяются командой
`tripPreparationOn`. Старый API не даёт квитанции исполнения; датчик показывает
«Отправлена без подтверждения».

## Другие найденные возможности

- `firmwareCheck` и `settingsCheck`: фактическая и ожидаемая версии, признак
  несовпадения. В HA добавлены диагностические индикаторы с атрибутами
  `actual` и `expected`. При проверке прошивка не совпадала с ожидаемой,
  настройки совпадали. Обновление прошивки или настроек не запускалось.
- `onlineState`, `isCarStateReady`, `carStateUpdatedAt`, `positionAt`, `warnings`:
  состояние соединения, готовность и свежесть данных. В HA добавлен текстовый
  датчик состояния связи; изменения связи и проверок версий обрабатываются
  даже при неизменном времени данных машины.
- `automations`: состояния автоматизаций, включая `lastResult`, попытки
  исполнения и повторов. В проверенной машине список пуст.
- `GET /client-bff-service/cars/{imei}/schedules`: расписания подготовки к поездке.
  В коде сайта есть время начала, дни недели, длительность, включение расписания
  и пара команд запуска/остановки. У проверенной машины расписаний нет.
  Создание, изменение расписаний и переключение автоматизаций не выполнялись.

Сигнал, зарядный разъём, температуры, запас хода и версия прошивки уже считывались
интеграцией до этой проверки. Живой тест подтверждает новый протокол для замка;
остальные названия команд найдены в `buttons`, но их исполнение не проверялось.
